# Очистка периода: табель, уголь, скот, агро

## Зачем

Ошибочные записи накапливаются: табель заполнили не на тех людей, уголь провели дважды, операцию по скоту
внесли не в тот день. Сегодня каждую строку приходится удалять по одной, а на телефоне табель за месяц
«очистить» нельзя вовсе — только снимать отметки по дню.

## Что решил владелец

- Очистка нужна **на сайте и на телефоне** (на телефоне — только владельцу, в настройках).
- Чистятся **все разделы учёта**: табель, уголь, скот, агро.
- Период — **день или месяц**; месяц подтверждается вводом слова «очистить».

## Рассмотренные способы

| Способ | Почему нет |
|---|---|
| Отдельный серверный маршрут `POST /clear` | Сервер пришлось бы учить тому, что уже умеет протокол синхронизации: `delete`-операции и обнуление отметки. Ещё один путь записи = ещё одно место, где можно разойтись с очередью и версиями. |
| «Жёсткое» удаление из БД на сервере | Ломает остальные устройства: они не узнают об удалении и пришлют записи обратно. |
| Только кнопка на сайте | В поле чинить табель удобнее с телефона; владелец выбрал оба места. |
| Автоочистка по расписанию | Не просьба; удаление истории по таймеру — худший вид сюрприза. |

## Не цели

- Не трогаем справочники: сотрудников, водителей, населённые пункты, категории скота, настройки (цены, часовой пояс).
- Не чистим старую модель табеля (`attendanceRecord`, Я/В/Б) и снимки (`timesheetSnapshot`) — это история.
- Нет «корзины» и отмены: очистка сразу уходит операциями удаления.
- Нет очистки «всё за всё время» одной кнопкой в интерфейсе.

## Анти-цели

- Нельзя удалять чужие разделы роли, у которой нет прав на запись: очистка идёт через тот же `RecordWriter`
  (`requireWrite`), что и обычные правки, а вход в экран на телефоне есть только у владельца.
- Нельзя молча потерять незаписанное: очистка — обычные операции, они встают в очередь и уезжают синхронизацией.

## Как устроено по платформам

Таблица «сущность → поле даты → способ» одинаковая на сайте (`web/src/lib/clear.ts`) и на телефоне
(`ru.kfh.tabel.clear`):

| Раздел | Записи | Поле даты | Как уходит |
|---|---|---|---|
| Табель | `hoursMark` | `day` | не удаляется, а обнуляется: `hours: null` — так приложение понимает «отметки нет» |
| Уголь | `coalSale`, `coalWorkDay`, `driverPayment` | `saleDate`, `day`, `paymentDate` | `delete`-операция |
| Скот | `livestockOperation` | `date` | `delete`-операция; причина забоя (`slaughterRecord`) уходит вместе со своей операцией, даже если у неё другая дата |
| Агро | `agroCalculation` | `createdAt` | `delete`-операция |

День записи считается **в зоне хозяйства** (Чита, UTC+9), а не в UTC: продажа в 20:00 UTC 30 ноября — это
1 декабря по местному времени.

**Сайт.** В каждом из четырёх разделов — карточка «Очистка <раздел>» (видна только владельцу): переключатель
День/Месяц, дата или месяц, счётчик «Будет удалено записей: N», поле подтверждения для месяца и кнопка.
Месяц без набранного слова не активен; день спрашивает обычное подтверждение.

**Телефон.** «Настройки» → «Владелец» → «Очистка данных» (строка видна только владельцу): те же четыре раздела,
день/месяц стрелками, счётчик, слово «очистить» для месяца, подтверждение диалогом. Счётчик считается по тому,
что уже лежит на телефоне; после очистки — «Удалено записей: N».

## Уточнения (мои решения)

- Слово подтверждения — «очистить» без учёта регистра и пробелов по краям; на сайте и на телефоне одно и то же.
- Скот: причины забоя ищутся **до** удаления операций, иначе связь `operationId` уже не восстановить (на этом
  поймал первый же тест).
- Агро чистится по `createdAt`: у расчёта нет деловой даты, только дата создания.
- После очистки выполняется обычная синхронизация; отдельного «уведомления» другим телефонам не нужно.
- Кнопка не даёт нажать себя, когда за период ничего нет.

## Оставлено на усмотрение исполнителя

- Как выглядит карточка на сайте и экран на телефоне (в рамках существующих стилей).
- Число запросов к базе при подсчёте: сейчас один `SELECT * FROM records` на пересчёт — на хозяйстве это
  сотни строк, оптимизация не нужна.
