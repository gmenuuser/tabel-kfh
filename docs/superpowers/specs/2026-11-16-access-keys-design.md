# Ключи доступа: подключение приложений по 4-значному коду

Дата: 2026-11-16. Решения владельца — из разговора 2026-11-16; всё помеченное «моё решение» предложено мной и может быть изменено владельцем.

## Зачем

14.11 владелец выбрал открытую регистрацию: приложение подключается само, без кода (способ 1 в `2026-11-14-open-apps-admin-design.md`). На практике это значит, что подключиться может любой, кто нашёл ссылку на APK, а в админке видно безымянные телефоны — не понять, чей это и кому что принадлежит. Владелец меняет это решение: вход в приложение — по 4-значному коду, который выдаёт админ; код выдаётся человеку, у человека есть имя и роль.

Успех: владелец заводит в админке ключ «Иван, табельщик», называет Ивану 4 цифры; Иван ставит приложение, вводит код — и работает только с табелем. В админке видно: Иван, Android, когда заходил. Потерял телефон — владелец перевыпускает код, старый телефон гаснет.

## Что решил владелец

1. **Входа по логину и паролю нет нигде, кроме владельца на сайте.** Почта + пароль — только админ.
2. **Приложения подключаются по 4-значному коду**, код генерирует админ в админ-панели.
3. **Код принадлежит человеку** (вариант A): имя и роль. Роль — та же, что была у помощников: всё / табель / уголь / скот / только чтение.
4. **Админ-панель расширяется**: ключи доступа (создать, перевыпустить, отозвать), люди и устройства, настройки хозяйства, копии, журнал.
5. **Сайт для обычных людей — только ссылки на скачивание приложений.** Вход по почте и паролю — отдельно, только админу.

## Рассмотренные способы

| Способ | Плюсы | Минусы | Итог |
|---|---|---|---|
| 1. Ключ = человек: на первом вводе кода сервер заводит пользователя (`users` + `memberships`) и устройство с `user_id` | Роли, права, аудит, синхронизация и `/devices` работают без правок; видно, кто что изменил; смена роли действует сразу на все устройства человека | Нужно ослабить `CHECK (email IS NOT NULL OR login IS NOT NULL)` из `002_logins.sql`; ключ живёт отдельно от человека | **Выбран** |
| 2. Ключ отдельно, роль на устройстве (`devices.role`, `devices.person_name`) | `users` не трогаем вовсе | Две системы прав одновременно; аудит по устройству, а не по человеку; смена роли требует обновить все устройства; проверки синхронизации переписываются | Отклонён |
| 3. Отдельная сущность `people` + `access_keys.person_id` | Самая чистая модель, многоразовые ключи на человека | Третья система личности в схеме, где уже есть `users` и `devices`; больше кода и миграций | Отклонён |
| (ранее) Открытая регистрация без кода | Человеку ничего вводить не надо | Кто угодно подключается; не видно, чей телефон; нельзя ограничить по разделам | Отменён владельцем 16.11 |

## Не цели

- Почтовый сервер. Сброс пароля админа остаётся как есть: код пишется в журнал сервера.
- Несколько хозяйств. По-прежнему одно.
- Пароли, PIN и «запомнить меня» в приложениях: код вводится один раз при подключении, дальше устройство живёт на своём токене.
- Защита файлов приложений по прямой ссылке (`/android/…`, `/ios/TabelKFH.ipa`). Убираются только ссылки с открытых страниц; доступ по прямой ссылке остаётся, на нём держится самообновление Android.

## Анти-цели (что сделает работу провалом, даже если «работает»)

- Код можно подобрать перебором за разумное время: 4 цифры — это 10 000 вариантов, поэтому окно перебора обязано быть коротким (лимиты и срок жизни кода, см. ниже).
- Человек с ролью «табель» может изменить уголь, скот или настройки — права проверяются на сервере, а не в интерфейсе.
- Кто-то, кроме админа, входит на сайт по паролю.
- Отозванный ключ оставляет телефон подключённым.
- Уже подключённые телефоны ломаются в момент выпуска (см. порядок выпуска).
- Потеря данных на устройстве, которое не отключали.

## Как устроено

### Сервер (`server/`)

- **Таблица `access_keys`** (миграция `004_access_keys.sql`): `id`, `farm_id`, `person_name`, `role`, `code_hash` (SHA-256 с «перцем» хозяйства — сам код не хранится), `expires_at`, `created_at`, `created_by`, `used_at`, `user_id` (человек, заведённый при первом вводе), `revoked_at`.
  - Активные (не использованные, не отозванные) коды уникальны внутри хозяйства: при совпадении администратор получает понятную ошибку «Такой код уже есть, нажмите «Создать» ещё раз».
- **Первое подключение**: `POST /devices/register` принимает `{ platform, name, code }`.
  - Код верный, не просрочен, не использован → в одной транзакции: пользователь (`name` = `person_name`, без почты и логина), членство с ролью ключа, устройство с `user_id`, `used_at` у ключа. Ответ — обычный токен устройства (32 байта), как сейчас.
  - Код неверный/просрочен/использован → 403 с текстом, различающим «Код неверный», «Код просрочен», «Код уже использован — попросите новый».
- **Права**: роль берётся из членства, как у помощников до 14.11. `entities.canWrite` уже умеет `manager` / `timesheet` / `coal` / `livestock` / `viewer`; ветка `app` остаётся только для старых записей.
- **Ограничения перебора** (моё решение): не больше 20 попыток подключения в час с одного IP, после этого адрес отдыхает 24 часа; не больше 200 неверных попыток в час на хозяйство — тогда подключение по коду приостанавливается на 30 минут, событие пишется в журнал (владелец видит попытку подбора). Счётчика «на конкретный код» нет: неверный ввод не указывает, к какому ключу он относился. Код живёт по умолчанию 24 часа, админ может выбрать от 1 до 30 дней. Если когда-нибудь покажется мало — код можно сделать 6-значным, это одна строка.
- **Админские запросы** (только владелец): `GET /keys` (список: имя, роль, статус, кем/когда привязан, телефон), `POST /keys` (новый человек: имя, роль, срок → ответ содержит сам код единственный раз), `POST /people/:id/keys` (ещё одно устройство существующему человеку — его нынешние устройства продолжают работать), `POST /keys/:id/reissue` (код взамен утерянного: устройства этого человека гаснут, выдаётся новый код), `POST /keys/:id/revoke` (устройства человека гаснут, ключи закрыты), `DELETE /keys/:id` (то же плюс ключ убирается из списка), `GET /people` и `PATCH /people/:id` (переименовать человека, сменить роль).
- **`PATCH /farm`**: поле `newDevicesAllowed` больше не управляет подключением — код и есть разрешение. Колонку в базе не удаляю (на ней висят старые проверки), но в админке переключатель убираю.
- **Вход админа** не меняется: `POST /auth/login`, только почта владельца, только `platform: 'web'`.
- **Аудит**: `key.create`, `key.reissue`, `key.revoke`, `device.pair` (с именем человека и платформой), `auth.login.failed` как сейчас.

### Сайт (`web/`)

- **Публичная страница** без входа: название хозяйства, две кнопки — «Android» и «iPhone», короткая инструкция по установке (Android 8.0+, iPhone через Sideloadly), кнопки «Скопировать ссылку». Данных хозяйства на ней нет.
- **Вход админа** — отдельный адрес (`#/admin`), почта + пароль + «Забыл пароль?». Ссылка на него с публичной страницы мелким текстом («Вход для администратора»).
- **После входа** — всё как сейчас плюс раздел **«Ключи»**:
  - создать: имя, роль, срок (1–30 дней), кнопка «Создать» → код показывается крупно, один раз, с кнопкой «Скопировать»;
  - список: имя, роль, статус (свободен / привязан: телефон, дата / просрочен / отозван), кнопки «Новый код» и «Отозвать»;
  - «Устройства» получают колонку с именем человека.

### Приложения (`android/`, `TabelKFH/`)

- **Android** (`ui/signin/ConnectScreen.kt`, `session/SessionManager.kt`): вместо кнопки «Подключиться» — поле «Код доступа» (4 цифры) и кнопка «Подключиться». `connect(code)` передаёт код в `/devices/register`. Новые причины отказа: «Код неверный», «Код просрочен», «Код уже использован». Отключённое устройство (401) — экран «Это устройство отключено, введите новый код от владельца».
- **iPhone** (`Features/SignIn/SignInView.swift`, `Sync/SessionStore.swift`): форма «почта/логин + пароль» заменяется на поле кода, как в Android. `POST /auth/login` из приложения больше не вызывается.
- Название устройства при подключении — модель телефона, как сейчас.

### Выпуск

Порядок, при котором никто не ломается (моё решение):
1. Сервер принимает **и код, и открытую регистрацию** (флаг `KEYS_REQUIRED=false` по умолчанию выключен).
2. Выходят новые Android и iPhone с полем кода; новые телефоны подключаются по коду, старые продолжают работать на своих токенах.
3. Владелец заводит ключи в админке; включённый `KEYS_REQUIRED=true` закрывает открытую регистрацию, устройства без человека отзываются.
4. Всё по «выкладывай» владельца: `deploy.sh` для сервера и сайта, `deploy-android.sh` для APK, IPA — через GitHub Actions.

## Уточнения (мои решения)

- **Уже подключённые телефоны** (роль `app`, без человека): остаются рабочими, пока владелец сам не нажмёт «Отключить все безымянные устройства» — отдельной кнопкой с подтверждением, не автоматически при включении обязательного кода. Иначе при выпуске разом гаснут все телефоны, включая телефон владельца (после миграции 003 он тоже устройство без человека), а вместе с ними стираются их неотправленные данные.
- **Телефон владельца** подключается по своему коду, как все: ключ «Виктор — телефон», роль «всё». Роль владельца телефону не даётся намеренно: с телефона нельзя менять настройки хозяйства, цену угля и настройки скота — это правило из спеки 14.11 остаётся.
- **Повторное подключение того же человека** (переустановил приложение, второй телефон): в админке две разные кнопки — «Ещё устройство» (выдаёт второй код тому же человеку, нынешние устройства продолжают работать) и «Новый код взамен утерянного» (гасит все устройства этого человека и выдаёт новый код). Один человек — одна роль на все его устройства.
- **Код хранится только как хеш**: показать его ещё раз невозможно, при утере — «Новый код». Это защищает от чтения базы, но не от перебора: за перебор отвечают лимиты.
- **Роль меняется на лету**: админ меняет роль человеку — членство обновляется, и следующая же синхронизация приносит устройству новые права (`/me` и `sessionOf` читают членство).
- **Удаление человека** («Отозвать»): устройства гаснут, членство остаётся, чтобы в журнале и истории осталось имя. Отдельного «удалить навсегда» не делаю.
- **Публичная страница** не показывает ни названия разделов, ни данных хозяйства: только ссылки и инструкция.
- **Файлы приложений** остаются доступны по прямой ссылке (нужно для автообновления Android).

## Проверено отдельным исполнителем (вопросы и куда они легли)

Перед планом спеку читал «свежий инженер», который не участвовал в разговоре. Его вопросы:

1. **Человек и ключи: как выдать второй код, что гасит перевыпуск, что делает отзыв** → разведено на две кнопки («Ещё устройство» / «Новый код взамен утерянного»), человек переиспользуется, отзыв не удаляет человека из журнала (см. «Уточнения»).
2. **Смысл лимита на код** → счётчика «на код» нет, лимиты только по IP и на хозяйство, с паузой и записью в журнал (см. «Ограничения перебора»).
3. **Когда гаснут старые безымянные телефоны** → никогда автоматически: отдельная кнопка с подтверждением, телефон владельца тоже переходит на код (см. «Уточнения»).
4. **Источник роли после привязки** → единственный источник — членство (`memberships`), одна роль на все устройства человека, меняется через `PATCH /people/:id` и доезжает со следующей синхронизацией (см. «Админские запросы» и «Уточнения»).

Открытым остался один вопрос, который решает владелец, а не исполнитель: **когда** нажимать «Отключить все безымянные устройства». Это единственный шаг, который стирает неотправленные данные на телефонах (401 → очистка локальной базы), поэтому он делается вручную и после того, как все нужные люди получили коды.

## Оставлено на усмотрение исполнителя

- Точные имена запросов, полей `access_keys` и текстов ошибок.
- Вёрстка публичной страницы, формы входа админа и раздела «Ключи» — в стиле существующих страниц.
- Как именно считать лимиты перебора (общий `limiter` в `app.ts` или отдельные) и где хранить «перчик» кода (переменная окружения).
- Формат флага «код обязателен» (переменная окружения или настройка хозяйства).
