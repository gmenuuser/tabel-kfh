# Android-приложение «Табель КФХ» — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** нативное Android-приложение с тем же набором функций, что iPhone-приложение `TabelKFH/` на `main`, работающее с хозяйством на `https://kfh.cubely.ru` по существующему протоколу синхронизации.

**Architecture:** два Gradle-модуля в `android/`. `core` — чистый Kotlin/JVM: доменные расчёты, записи синхронизации (data-классы с именами полей как у сайта), API-клиент, движок синхронизации против интерфейса `LocalStore`; всё тестируется на JVM без эмулятора. `app` — Android: Room хранит записи **обобщённо** (одна таблица `records` с JSON `data`, как IndexedDB у сайта) плюс очередь операций, курсор и не принятые; экраны на Compose читают записи через `core`-кодек. Новая сущность или поле не требуют миграции Room.

**Tech Stack:** Kotlin 2.x, Jetpack Compose (Material 3, BOM), Navigation Compose, Room 3 (`androidx.room3:room3-runtime` / `room3-compiler` 3.0.3 через KSP, плагин `androidx.room3`), kotlinx.serialization-json, kotlinx.coroutines, OkHttp 4 (+ MockWebServer в тестах), androidx.security-crypto (токен), JUnit 4. Версии AGP/Kotlin/Compose BOM — последние стабильные, совместимые с JDK 17 и compileSdk 36 (оба установлены на этом ПК); фиксируются в `android/gradle/libs.versions.toml` в Task 1.

**Spec:** `docs/superpowers/specs/2026-11-08-android-design.md` (одобрен владельцем 2026-11-08). Образцы поведения: `TabelKFH/` (Swift), `web/src/lib/*` и `web/src/pages/*` (формат полей), `server/README.md` (протокол), `server/src/entities.ts` (сущности, роли, проверки).

## Global Constraints

- `applicationId` / пакет: `ru.kfh.tabel` (app), `ru.kfh.core` (core). Название приложения: «Табель КФХ».
- minSdk 26 (Android 8.0); targetSdk/compileSdk 36. Никаких Google Play Services (ни Firebase, ни входа через Google, ни карт).
- Адрес сервера зашит: `https://kfh.cubely.ru`. `POST /auth/login {login, password, platform: "android", deviceName: Build.MANUFACTURER + " " + Build.MODEL}`.
- Формат полей: как пишет сайт (`web/src/pages/*.tsx`); правила `TabelKFH/Sync/SyncCodec.swift` (поле = имя свойства, `…Raw` без `Raw`; даты ISO 8601 UTC с миллисекундами и `Z`; UUID строчными; пустое необязательное — `null`; деньги — копейки `Long`; масса, головы — целые). Расхождение iPhone и сайта → пишем как сайт и записываем в отчёт задачи.
- «День» — `YYYY-MM-DD` в часовом поясе хозяйства (`/me` → `farm.timeZone`, по умолчанию `Asia/Chita`), **не** телефона. В `core` дни — `java.time.LocalDate`, моменты — `Instant`.
- Все тексты интерфейса — русские, дословно как на iPhone (брать строки из соответствующих `TabelKFH/Features/**.swift`).
- Тёмно-зелёный основной цвет и акценты — значения из `TabelKFH/App/Theme.swift`; светлая и тёмная тема.
- Одно действие пользователя = одна операция в очереди на каждую затронутую запись, в одной транзакции Room с изменением записи.
- Ключ подписи и пароли не попадают в репозиторий (он публичный) и не печатаются в логах.
- Локальные команды (Git Bash, из корня репозитория): `cd android && ./gradlew <задача>`; SDK — `android/local.properties` с `sdk.dir=C\:\\Users\\Hesya\\AppData\\Local\\Android\\Sdk` (файл в `.gitignore`). Обязательная проверка — зелёный CI `android.yml`.
- Тесты-переносы iPhone: «перенести `X.swift`» = каждое `XCTAssert…` того файла, относящееся к перенесённому коду, становится тем же утверждением с теми же значениями в JUnit; тесты UI/SwiftData-специфики пропускаются с пометкой в отчёте.

## Review Focus

1. **Часовой пояс телефона ≠ хозяйства** (телефон в Москве, хозяйство в Чите): «Сегодня», ключи `hoursMark`/`coalWorkDay`, закрытие дня — по Чите. Тест в Task 2 и Task 10.
2. **Приложение убито посреди синхронизации** (Honor агрессивно выгружает приложения): очередь переживает перезапуск, операция уходит снова с тем же `opId`, продажа не задваивается. Тест в Task 7 и Task 8.
3. **Двойное нажатие «СОХРАНИТЬ ПРОДАЖУ» / «Выплатить»** на медленном телефоне: одна продажа, одна выплата. Тест в Task 11.
4. **Ввод с запятой и пробелами** («2,5», «6 500», «1 200,50») с русской клавиатуры: разбирается так же, как на iPhone. Тест в Task 4.
5. **Крупный системный шрифт (×1.3–2.0) и экран 4,7"**: главные кнопки и форма продажи не обрезаются, ключевые кнопки достижимы прокруткой. Тест в Task 17.
