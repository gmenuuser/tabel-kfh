# Модуль «Продажа угля» — план интеграции

Spec: `docs/coal-spec.md`. Build and verification as in `2026-11-06-tabel-kfh.md` (CI is the only compiler;
every stage ends with a green run). The timesheet part is not changed except where listed.

## Rulings (controller)

- **Store migration.** The owner's phone has a V1 store. The four V1 model classes are not edited, so
  `SchemaV1` keeps describing the shipped store; `SchemaV2` = the same four + six coal models; one
  lightweight stage V1 → V2 (entities only added). A test creates a V1 store, opens it with the app's
  container and checks the data. If that test fails, fall back to frozen nested copies.
- **Money** is `Int` kopecks, **mass** is `Int` kilograms (1 т = 1000 кг, input up to 3 decimals):
  coal = kg × price per ton / 1000, rounded half up to a kopeck. No `Double` in money.
- **Prices in a sale**: list snapshots (`coalPricePerTonSnapshot`, `deliveryPriceSnapshot`) + actual
  amounts (`coalAmount`, `deliveryPrice`, `totalAmount`). Manual correction changes the actual amounts only;
  «было» = tons × snapshot + delivery snapshot.
- **Driver pay**: location's `driverPayment` (nil = same as delivery price) copied into the sale;
  editable in the sale; 0 and no driver for the own vehicle. A hired sale without a driver is refused.
- **Debt** is never stored: accrued (Σ hired sales' driver pay) − paid (Σ payments), all computed from rows.
  Closing a day stores only a snapshot of its totals for history; reports always recompute. A payment above
  the current debt is refused (protects from a typo such as 20000 instead of 2000).
- **Closed day**: sales of that day cannot be added, edited, moved in or out, or deleted until
  «Открыть день для редактирования»; payments are not tied to days. Re-closing refreshes the snapshot.
- `WorkDay` from the spec is named `CoalWorkDay` (Domain/WorkDay.swift already holds the farm calendar).
- **Locations**: «Удалить» hides (`isActive = false`); sales keep the name snapshot; adding a hidden name
  again shows it again. Defaults (6500, Новоцурухайтуй 1000, Приаргунск 1200) are seeded once with the
  coal settings row. Drivers are not seeded.
- **Drivers**: delete only without sales and payments, otherwise archive (history stays, hidden from the
  picker); restore from archive.
- **Navigation**: the five timesheet tabs stay. Home gets a large «Продажа угля» card that opens the coal
  module full screen with its own tabs: Продажи, Итоги дня, Водители, История, Цены, and «Табель» to go back.
  The app reopens in the module when it was left there.
- **Backup**: one file for everything. `BackupPayload.coal` optional (older files keep their checksum);
  `schemaVersion` 2, 1 still restorable; a file without coal data keeps the current coal data.
- **Reports**: own PDF (A4 portrait, Arial) and XLSX writers for the day and the month report,
  `ZipWriter` and `XLSXWriter.escape/column` reused; AirPrint and Share Sheet as in the timesheet.

## Stages

1. Models + Schema V2 + migration test + `CoalMath` (money, tons, parsing, formatting) + tests.
2. Services: `CoalSettingsService`, `DriverService`, `CoalSaleService`, `DriverPaymentService`,
   `CoalDayService`, `CoalReportBuilder` (day, month) + tests of spec scenarios 1–7.
3. Backup integration + tests.
4. Day / month PDF and XLSX + tests + review samples.
5. UI: module shell, today's sales, new/edit sale, drivers, day totals + close day, history, prices,
   Home entry; UI walkthrough with screenshots.
6. README, final review, IPA.
