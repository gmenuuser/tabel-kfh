# Сервер «КФХ — Учёт»

Общая база данных хозяйства (PostgreSQL) и API для iPhone, Android и сайта: учётные записи, хозяйство,
помощники с ролями, устройства, синхронизация с версиями записей и конфликтами, файлы, резервные копии.

Сейчас сервер работает **на этом компьютере** в Docker. Телефоны подключатся к нему только из той же
домашней сети. Для работы из любого места нужен настоящий сервер — см. «Перенос на сервер».

## Запуск на этом компьютере

```sh
cd server
cp .env.example .env          # и впишите длинный случайный пароль базы
docker compose up -d --build  # база + API на http://<адрес компьютера>:8080
docker compose logs -f api    # журнал; сюда же пишутся коды восстановления пароля
docker compose down           # остановить (данные сохраняются в томах Docker)
```

Проверка: `http://127.0.0.1:8080/health` → `{"ok":true}`.

## Сайт

Сайт (`web/`, React + TypeScript) собирается вместе с сервером и открывается по его адресу:
`http://<адрес компьютера>:8080`. Работает и без интернета: данные и очередь изменений хранятся в браузере
(IndexedDB), отправляются сами через секунду после правки, при появлении сети, при возврате на вкладку,
каждую минуту и по кнопке «Синхронизировать сейчас». Полоса под меню показывает состояние: «Все данные
синхронизированы», «Нет интернета… Ожидают отправки: N», «Ошибка синхронизации», конфликты.

Разработка сайта: `cd web && npm install && npm run dev` (запросы к API идут на :8080).
Тесты сайта (`npm test` в `web/`) гоняют его синхронизацию против настоящего сервера и базы.

Офлайн-открытие страницы (service worker) браузеры разрешают только на https или localhost; на адресе
домашней сети по http сайт работает, пока вкладка открыта, а после закрытия без сети не откроется.

**Одинаковые id на всех платформах.** Записи, которые должны быть одни на хозяйство или на «человека и день»,
получают id из имени: первые 16 байт SHA-256 от UTF-8 строки, версия 8 (`b[6] = b[6] & 0x0f | 0x80`),
вариант 10. Имена: `hoursMark:<employeeId>:<YYYY-MM-DD>`, `coalSettings`, `farmSettings`, `livestockSettings`, `coalWorkDay:<YYYY-MM-DD>`,
`deliveryLocation:<название>`, `livestockCategory:<вид>:<название>`. День — по часовому поясу хозяйства.
Снятая отметка часов — `hours: null` (запись остаётся, чтобы её можно было поставить снова).

## Тесты

```sh
npm install
npm run test:db     # один раз: тестовый PostgreSQL в Docker на порту 55432
npm run typecheck
npm test
```

Тесты проверяют на настоящей базе: регистрацию и разделение хозяйств, приход изменений на другие устройства,
повторную отправку без дублей (продажи, выплаты, забой), объединение правок разных полей, конфликт при правке
одного поля и его решение, запрет частичного применения денежных записей, проверки денег и поголовья на
сервере, удаление и невозврат удалённого, роли помощников, отзыв устройства, восстановление пароля, файлы без
повторной загрузки, серверную копию с проверкой и восстановлением, ограничение частых попыток входа.

## Роли

| Роль | Может |
|---|---|
| `owner` | всё, помощники, устройства, копии |
| `manager` | все модули |
| `timesheet` | только табель и сотрудников |
| `coal` | только уголь и водителей |
| `livestock` | только скот |
| `viewer` | всё смотреть, ничего не менять |

Права проверяет сервер. Владелец сам заводит помощника: `POST /members {login, password, role}` (логин — 3–32
латинских букв, цифр, `_` и `-`, без почты; роль не `owner`). Помощник входит `POST /auth/login {login, password}`.
Владелец меняет пароль помощника `POST /members/{id}/password {password}` и роль `PATCH /members/{id} {role}` —
в обоих случаях все устройства помощника отключаются и он входит заново.

Регистрация новых хозяйств закрыта: `POST /auth/register` отвечает 403, пока в окружении не задано
`REGISTRATION_OPEN=true`. Открыта ли она, видно без входа: `GET /auth/config` → `{registrationOpen}`.

## Протокол синхронизации (для iPhone, Android и сайта)

Все запросы, кроме входа, с заголовком `Authorization: Bearer <токен устройства>`. Токен выдаётся при
регистрации или входе и хранится в защищённом хранилище устройства (Keychain, Android
Keystore). На сервере хранится только его SHA-256.

**Запись** — `entity` (тип), `id` (UUID, создаётся на устройстве), `version` (номер версии на сервере),
`data` (поля как в моделях iPhone, camelCase), `deleted`. Деньги — целые копейки, масса — граммы или
килограммы целым числом, даты — ISO 8601 в UTC с `Z`. Типы записей: `GET /entities`.

**Отправка** — `POST /sync/push`:

```json
{ "ops": [ { "opId": "<UUID операции>", "entity": "coalSale", "recordId": "<UUID записи>",
             "kind": "upsert", "baseVersion": 0, "fields": { "kilograms": 2000, "...": "..." } } ] }
```

- `opId` — один на одно действие пользователя; повторная отправка возвращает прежний результат
  с `repeated: true` и ничего не меняет;
- `baseVersion` — версия записи, которую устройство видело последней (0 для новой);
- `fields` — только изменённые поля; `kind: "delete"` — мягкое удаление.

Ответ на каждую операцию: `applied` (принято), `partial` (часть полей принята, остальные — конфликт),
`conflict` (ничего не принято, обе версии сохранены), `rejected` (ошибка в данных или нет прав, с `errors`).
Из очереди устройства удаляются только операции с ответом `applied`, `partial`, `conflict` или `rejected`;
при обрыве связи операция остаётся в очереди и отправляется снова.

**Получение** — `GET /sync/pull?since=<число>` → `{changes, next, more}`. Устройство хранит `next` и при
следующей синхронизации передаёт его в `since`; при `more: true` запрашивает ещё раз.

**Конфликты.** Поле, изменённое на другом устройстве после `baseVersion`, не перезаписывается: сохраняются оба
значения (`GET /conflicts`), владелец выбирает (`POST /conflicts/{id}/resolve {choice: "server"|"client"}`).
Продажи, выплаты, закрытые дни, операции со скотом и забой не объединяются по полям: при любом конфликте не
применяется ничего, решение — для всего изменения целиком. Удалённая запись не возвращается правкой со старого
устройства — это тоже конфликт. Удаление записи, которую уже изменили на другом устройстве, — конфликт.

**Проверки сервера**: итог продажи = уголь + доставка; своя машина без долга водителю; наёмная — с водителем;
выплата больше нуля; часы — 0, 4, 8 или 12; поголовье ни на какую дату не уходит в минус.

## Остальное API

- `POST /auth/register`, `/auth/login`, `/auth/logout`, `/auth/reset-request`, `/auth/reset`
- `GET /auth/config` — открыта ли регистрация
- `GET /me`, `PATCH /farm` (название, регион, руководитель, часовой пояс; по умолчанию Приаргунский район,
  Забайкальский край, `Asia/Chita`)
- `GET /members`, `POST /members`, `POST /members/{id}/password`, `PATCH /members/{id}`, `DELETE /members/{id}`
- `GET /devices`, `POST /devices/{id}/revoke` — отозвать доступ потерянного устройства
- `PUT /files` (тело — файл; одинаковый файл не хранится дважды), `GET /files/{id}`
- `POST /backups`, `GET /backups`, `GET /backups/{id}/verify`, `POST /backups/{id}/restore {confirm: true}`
- `GET /audit` — журнал важных действий

Полная копия всей базы: `scripts/backup-db.sh` (pg_dump в `backups/`).

## Перенос на сервер (когда решите)

Понадобятся от владельца:

1. **Сервер (VPS)** у российского хостинга: 1–2 ГБ памяти, Ubuntu, Docker. Адрес и доступ по SSH.
2. **Домен** (например, `kfh-uchet.ru`) — для HTTPS; без HTTPS iPhone и браузеры не пустят приложение
   к серверу из интернета. Сертификат выпускается бесплатно (Let's Encrypt через Caddy).
3. **Почта для писем** (SMTP: адрес, логин, пароль) — чтобы коды восстановления пароля приходили письмом.
   Пока код пишется в журнал сервера.

Секретов в коде нет: пароль базы — в `.env` на сервере, в приложения попадает только адрес сервера.
