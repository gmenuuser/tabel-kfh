# Выкладка сервера на VDS (kfh.cubely.ru)

Сервер работает на том же VDS, что и Cubely (37.230.113.40), в `/opt/kfh`: API на `127.0.0.1:8090`, база наружу не открыта,
снаружи — nginx с сертификатом. Файлы и конфиги Cubely не трогаются.

**Первая выкладка делается только после слова владельца «выкладывай».**

## Первая выкладка

0. Сначала только просмотр, ничего не меняется: `bash server/deploy/deploy.sh root@37.230.113.40 --preflight`.
   Контролёр читает вывод (как Cubely чистит restic, его монитор, порты nginx, проекты docker, память) и только потом даёт добро на `--first-time`.

1. На Рег.ру: A-запись `kfh` → `37.230.113.40`. Проверка: `nslookup kfh.cubely.ru 8.8.8.8`.
2. Всё закоммичено (выкладывается только то, что в `HEAD`), затем:
   `bash server/deploy/deploy.sh root@37.230.113.40 --first-time`
   Сборка идёт на самом VDS (`up --build`), поэтому выкладывать лучше в тихий час. Скрипт создаст `/opt/kfh/server/.env` со случайным паролем базы, поднимет контейнеры, подключит сайт в nginx
   (ссылкой в `sites-enabled`), получит сертификат и включит ночной бэкап.
3. Проверка: `curl -fsS https://kfh.cubely.ru/health` → `{"ok":true}`; `https://cubely.ru` и `https://panel.cubely.ru` отвечают как раньше.

## Обновление

`bash server/deploy/deploy.sh` (хост по умолчанию `root@37.230.113.40`). Данные и `.env` сохраняются.

## Подключение устройств

Регистрации хозяйств нет. Телефоны подключаются сами, владелец отключает или переименовывает их на сайте
(и может закрыть подключение новых переключателем `newDevicesAllowed`).

## Бэкап

Каждую ночь в 03:30 (МСК) `kfh-backup.timer` делает `pg_dump` в `/var/backups/kfh` (хранятся 14 последних) и отправляет
папку в restic-репозиторий Cubely (тег `kfh`). Проверка:

    ssh root@37.230.113.40 '/usr/local/sbin/kfh-backup'                       # сделать бэкап сейчас
    ssh root@37.230.113.40 'bash /opt/kfh/server/deploy/check-backup.sh'      # восстановить во временную базу и сравнить число записей
    ssh root@37.230.113.40 'systemctl list-timers kfh-backup.timer'

В бэкап входят дамп базы (`kfh-*.dump`) и архив загруженных файлов (`files-*.tar`). Настройки restic лежат в `/etc/kfh/restic.env`
(создаются при `--first-time`; адрес репозитория берётся чтением из `/root/.cubely-restic.env`, затем из скрипта Cubely — закомментированные строки не в счёт;
пароль и ключи S3 — из файлов Cubely, их наличие проверяется). Поиск адреса и шаг tar проверяются локально: `bash server/deploy/test-deploy-scripts.sh`.
Если во время бэкапа загрузили файл, tar выходит с кодом 1 — это предупреждение, если архив читается целиком; иначе бэкап падает.
`--first-time` заканчивается настоящим бэкапом и `restic snapshots --tag kfh`: если цепочка сломана, он упадёт сразу.
Старые снимки kfh удаляются командой `forget` (14 дней, 4 недели) без `--prune`: место освобождает бэкап Cubely.
`check-backup.sh` восстанавливает и локальный дамп, и из последнего снимка restic — только самые новые дамп и архив файлов.

## Важно

- Имя compose-проекта `kfh` (строка `name: kfh` в `compose.prod.yml`) менять нельзя никогда: тома с данными названы по нему.
- certbot использует уже существующий ACME-аккаунт на этой машине.
- Если `nginx -t` не проходит, скрипт убирает ссылку нашего сайта из `sites-enabled` и останавливается; nginx с неверным конфигом не перезагружается.
